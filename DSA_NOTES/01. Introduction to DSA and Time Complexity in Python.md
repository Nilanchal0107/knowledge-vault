# 🧠 1. What is Data?

**Data** = Raw information used by programs.

### Examples

* Numbers
* Names
* User records
* Program inputs

### Python Example

```python
a = 5
b = 10
print(a + b)
```

Here **5** and **10** represent **data values**.

---

# 🏗 2. What is a Data Structure?

A **Data Structure** organizes data in memory so it can be accessed efficiently.

Think of it like **containers used to store things**.

---

## Everyday Analogy

| Data  | Container               |
| ----- | ----------------------- |
| Water | Bottle / Bucket / Glass |

---

## Programming Data Structures

| Data Structure | Purpose                  |
| -------------- | ------------------------ |
| Array / List   | Store sequential data    |
| Linked List    | Dynamic memory structure |
| Stack          | LIFO operations          |
| Queue          | FIFO operations          |
| Tree           | Hierarchical data        |
| Graph          | Network relationships    |

---

### Python Example

```python
arr = [10, 20, 30, 40]
```

Here the **list acts as a data structure**.

# ⏱ 4. Why Do We Need Time Complexity?

Two programs may solve the same problem but **one may be faster**.

Example:

| Program   | Execution Time |
| --------- | -------------- |
| Program A | 1 second       |
| Program B | 10 seconds     |

Obviously we choose **Program A**.

To measure efficiency we use:

# ⏳ Time Complexity

Time complexity describes **how runtime increases as input size increases**.

Input size is represented as:

```
n
```

Example growth:

```
10 → 100 → 1000
```

---

# 📏 5. Rules of Time Complexity

## Rule 1 — Ignore Constants

Example:

```
2n + 5
```

Becomes:

```
O(n)
```

Constants are ignored for large inputs.

---

## Rule 2 — Focus on Dominant Term

Example:

```
n² + n + 5
```

Dominant term:

```
n²
```

Final complexity:

```
O(n²)
```

---

# 📊 6. Order of Time Complexity (Best → Worst)

| Complexity | Name         |
| ---------- | ------------ |
| O(1)       | Constant     |
| O(log n)   | Logarithmic  |
| O(n)       | Linear       |
| O(n log n) | Linearithmic |
| O(n²)      | Quadratic    |
| O(n³)      | Cubic        |
| O(2ⁿ)      | Exponential  |

Better algorithms have **smaller growth rates**.

---

# 🔍 7. Types of Time Complexity Analysis

### 🟢 Best Case — Ω (Omega)

Minimum time required.

Example: Searching first element.

---

### 🟡 Average Case — Θ (Theta)

Expected runtime over many inputs.

---

### 🔴 Worst Case — O (Big-O)

Maximum possible time.

Most commonly used in **interviews and algorithm analysis**.

---

# 📦 8. Constant Time Complexity — O(1)

Execution time **does not depend on input size**.

### Example

```python
x = 5
print(x)
```

### Characteristics

* No loops
* No recursion
* Fixed operations

---

# 📈 9. Linear Time Complexity — O(n)

Runtime increases **proportionally with input size**.

### Example

```python
for i in range(n):
    print(i)
```

Example growth:

```
n = 10 → 10 operations
n = 100 → 100 operations
```

---

### Multiple Independent Loops

```python
for i in range(n):
    print(i)

for j in range(n):
    print(j)
```

Complexity:

```
O(n + n)
```

After ignoring constants:

```
O(n)
```

---

# 🔁 10. Quadratic Time Complexity — O(n²)

Occurs when **nested loops** exist.

### Example

```python
for i in range(n):
    for j in range(n):
        print(i, j)
```

Example:

```
n = 5
```

Operations:

```
5 × 5 = 25
```

Final complexity:

```
O(n²)
```

---

# 🔁 11. Cubic Time Complexity — O(n³)

Three nested loops.

```python
for i in range(n):
    for j in range(n):
        for k in range(n):
            print(i, j, k)
```

Operations:

```
n × n × n
```

Complexity:

```
O(n³)
```

---

# 📉 12. Logarithmic Time Complexity — O(log n)

Occurs when **input size is divided every iteration**.

### Example

```python
while n >= 1:
    print("Hello")
    n = n // 2
```

Example execution:

```
16 → 8 → 4 → 2 → 1
```

Iterations:

```
log₂(16) = 4
```

Complexity:

```
O(log n)
```

---

## Doubling Case

```python
i = 1

while i < n:
    print(i)
    i = i * 2
```

Example:

```
1 → 2 → 4 → 8 → 16
```

Also results in:

```
O(log n)
```

---

# ⚡ 13. Quick Method to Identify Time Complexity

| Code Pattern                     | Complexity |
| -------------------------------- | ---------- |
| No loop                          | O(1)       |
| One loop                         | O(n)       |
| Two nested loops                 | O(n²)      |
| Three nested loops               | O(n³)      |
| Divide input by 2 each iteration | O(log n)   |

---

# 📌 14. Dominant Term Rule

If a program contains:

```
O(1)
O(log n)
O(n)
O(n²)
```

The **largest term dominates**.

Final complexity:

```
O(n²)
```

---

# 🧪 15. Example Program

```python
print(n)

for i in range(n):
    print("Hello")

for i in range(n):
    for j in range(n):
        print("Chai")

while n >= 1:
    print("DSA")
    n = n // 2
```

### Individual Complexities

| Code         | Complexity |
| ------------ | ---------- |
| print(n)     | O(1)       |
| Single loop  | O(n)       |
| Nested loops | O(n²)      |
| Halving loop | O(log n)   |

### Final Complexity

```
O(n²)
```

Because **quadratic dominates**.

---

# 🎯 Key Takeaways

✔ Ignore constants
✔ Focus on dominant term
✔ Nested loops → multiply complexity
✔ Sequential loops → add complexity
✔ Divide by 2 each iteration → **O(log n)**
