# 🤖 AI Programming Prompting — Revision Notes
> Based on: [I Have Spent 500+ Hours Programming With AI. This Is What I Learned](https://www.youtube.com/watch?v=91B_v-wOaws)

---

## 🧠 Core Philosophy

> **"AI is a multiplier — it multiplies what you already know."**

- AI does **not** replace your brain; it amplifies your existing skills
- Good habits → AI amplifies them ✅
- Bad habits (skipping tests, no documentation) → AI amplifies those too ❌
- **Don't let AI think for you.** Let it type for you, not think for you.

---

## Tip 1 — Learn to Program First

- AI is only as useful as the knowledge you bring to it
- You cannot outsource your brain if you don't have one to start with
- Knowing programming helps you catch AI mistakes and guide it better

---

## Tip 2 — Be As Specific As Humanly Possible

Most bad AI results come from **vague prompts**, not bad AI.

### The 3 Levels of Prompting

| Level | Type | Description | Result |
|---|---|---|---|
| 1 | 🧟 Smooth Brain | e.g., *"Build Google Docs"* | Nothing / slop |
| 2 | 😐 Average | More details, but non-technical | Errors, no styling, guesswork |
| 3 | ✅ Ideal | Full technical details, stack, docs, images, commands | Works first try |

### What to Include in a Strong Prompt
- Exact tech stack
- How features should work
- Terminal commands
- Links to documentation / resources
- Screenshots or designs (show, don't just tell)
- Relevant files

### 💡 Lazy Hack
Write a basic prompt with all technical info, then say:
> *"Enhance this prompt with LLM best practices."*

AI will make it more detailed and perform better.

## Tip 3 — Break Big Tasks Into Smaller Tasks

> **"The smaller the task, the better the results."**

- AI is great at small tasks, not complex multi-part ones
- Break big problems into smaller, well-defined pieces
- If you **can't** break it down → you don't understand the problem well enough yet
- This is fundamental engineering — plan → break down → execute

### Workflow
```
1. Understand the problem
2. Plan the solution
3. Break into small tasks
4. Prompt AI with each small task (with detail)
```

---

## Tip 4 — The 3-Section Prompt Pattern

Use this structure for every non-trivial prompt:

```
1. TASK
   → Be as descriptive as possible about what you want

2. BACKGROUND INFORMATION
   → Files, documentation, images, user flow screenshots

3. DO NOT SECTION
   → What NOT to touch
   → What NOT to change
   → Only what it should be modifying
```

This pattern significantly reduces mistakes and unwanted changes to existing code.

---

## Tip 5 — Tell AI What You DON'T Want

- Explicitly listing what to avoid is **just as important** as describing what you want
- Prevents AI from breaking working code
- Prevents AI from making assumptions about architecture

---

## Tip 6 — Tell AI to Remember (Rules / Guidelines Files)

Use a persistent memory file so AI has consistent project context.

### File Names (varies by tool)
- `guidelines.md`
- `agent.md`
- `.cursorrules` (Cursor)

### What to Put in This File
- What the project is about
- Tech stack
- Important commands
- Workflow conventions
- Project-specific rules and constraints

### How to Create It
- Write it yourself
- Ask AI to analyze the codebase and generate it
- Use templates from online (search for your tech stack)
- Copy rule templates provided by the tool's company

---

## Tip 7 — Use MCPs (Model Context Protocol)

MCPs are tools that **extend what AI can do** — like plugins.

### Recommended MCPs (for web dev)

| MCP | What It Does |
|---|---|
| **Context7** | Auto-fetches documentation — no more copy-pasting docs |
| **Next.js Dev Tools** | Gives AI build errors, project state, page metadata, logs |
| **Chrome Dev Tools** | Access to layout shifts, console errors, network requests, performance |

### Key Takeaway
- Find MCPs suited to **your** tech stack (databases, cloud, third-party services)
- The right combo of MCPs makes a massive difference

---

## Tip 8 — Always Give AI a Way to Verify Its Work

> **"AI should never just write code. It also needs a way to verify the code."**

### Verification Methods
- Unit / integration tests
- Running the app in browser
- CLI commands
- CI/CD pipelines
- For frontend: use a visual/browser MCP tool

### Rule
- Either create tests yourself, or tell AI to generate them **and make sure they all pass**
- Always verify that verification methods themselves are working correctly

## ✅ Summary Checklist — Before You Prompt AI

- [ ] Do I understand the problem well enough to break it down?
- [ ] Have I broken the task into small, focused pieces?
- [ ] Is my prompt technically detailed (stack, commands, docs)?
- [ ] Have I included relevant files, images, or links?
- [ ] Have I added a "Do Not" section?
- [ ] Does my project have a `guidelines.md` / rules file?
- [ ] Are the right MCPs set up for my project?
- [ ] Is there a way for AI to verify the code it writes?
